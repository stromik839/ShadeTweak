# ShadeTweak — колір/прозорість фону шторки HyperOS без блюру

## Що це і чому саме так

`deviceLevelList` вимикає блюр, але сірий фон-заміна зашитий у ресурсах
`MiuiSystemUI.apk` — окремого `settings put` для нього нема. Щоб зробити
цей фон прозорим (а не просто сірим), потрібне живе перехоплення коду
системного UI. Такого рівня доступу звичайний KernelSU-модуль (файловий
overlay + boot-скрипти) не дає — для цього потрібен Zygisk-хук (LSPosed).

Тому пакет складається з двох частин:

1. **ShadeTweak (цей проєкт)** — LSPosed-модуль. Він робить фактичну
   роботу: перехоплює клас `ShadeSolidBackgroundController` у SystemUI й
   підміняє два його поля (`solidAlpha`, `solidRGB`) значеннями, які ти
   задаєш у власному екрані налаштувань модуля.
2. **shadetweak-kernelsu-check.zip** (окремо) — звичайний KernelSU-модуль
   у .zip форматі. Він НІЧОГО не хукає — тільки перевіряє при завантаженні,
   чи встановлені залежності (ZygiskNext, LSPosed, сам ShadeTweak), і пише
   звіт у лог. Файловий KernelSU-модуль фізично не може робити те, що
   робить LSPosed-модуль — це різні механізми.

## Знахідки (реальний аналіз твого systemui.zip)

- Пакет: `com.android.systemui`
- Клас: `com.miui.systemui.shade.blur.ShadeSolidBackgroundController`
- Поля: `int solidAlpha`, `int solidRGB`
- Точки перехоплення: `updateWindow()` (застосування) та
  `access$updateResources(ShadeSolidBackgroundController)` (перерахунок
  при зміні теми)

Це підтверджено структурним розбором байткоду (класи/поля/методи), НЕ
повним дизасемблюванням логіки методів — тобто я на 100% впевнений, що ці
поля й методи існують саме так у твоїй збірці, але не перевіряв на
реальному пристрої, чи саме ЦІ два методи - єдине місце, де
solidAlpha/solidRGB використовуються.

## Встановлення (по кроках)

### Передумови на телефоні
1. ZygiskNext — встановлюється як звичайний KernelSU-модуль
   (github: Dr-TSNG/ZygiskNext, розділ Releases).
2. LSPosed (для ZygiskNext) — github: JingMatrix/LSPosed, розділ Releases.
3. Реюут після встановлення обох.

### Збірка ShadeTweak — варіант A: GitHub Actions (нічого не гріє твій ноутбук)
Компіляція йде на серверах GitHub, безкоштовно. Потрібен лише акаунт
GitHub і `git push` — жодного локального навантаження.

1. Створи новий репозиторій на github.com (можна приватний).
2. Заливь туди вміст цієї папки `ShadeTweak/` (разом з `.github/`):
   ```
   git init
   git add .
   git commit -m "init"
   git branch -M main
   git remote add origin https://github.com/ТВІЙ_НІК/НАЗВА_РЕПО.git
   git push -u origin main
   ```
3. На сторінці репозиторію відкрий вкладку **Actions** — збірка запуститься
   автоматично (workflow `.github/workflows/build.yml`).
4. Коли завершиться (зелена галочка, зазвичай 2-4 хв) — зайди у сам run,
   внизу розділ **Artifacts** → завантаж `ShadeTweak-apk` (це zip з apk
   всередині).
5. Перекинь apk на телефон і встанови.

### Збірка ShadeTweak — варіант B: Android Studio локально
Якщо все ж хочеш зібрати на своїй машині (переконайся спершу, що з
залізом усе гаразд):
1. Відкрий папку `ShadeTweak/` в Android Studio.
2. Дочекайся Gradle sync (підтягне Kotlin + Xposed API автоматично).
3. Build → Build Bundle(s)/APK(s) → **Build APK(s)** (не Bundle).
4. Готовий apk (debug-варіант, підписаний автоматично, одразу
   встановлюється): `app/build/outputs/apk/debug/app-debug.apk`.
   Release-варіант без налаштованого підпису НЕ встановиться —
   лишайся на debug, для локального використання цього достатньо.

### Встановлення apk
1. Перекинь apk на телефон, встанови (`pm install` через Termux або
   звичайний встановлювач).
2. Відкрий LSPosed Manager → Modules → знайди "Shade Tweak" → онови
   галочку область застосування вже виставлена на `com.android.systemui`
   через маніфест, але перевір вручну, якщо LSPosed її не підхопив.
3. Перезапусти SystemUI або перезавантаж телефон.

### Налаштування кольору
Відкрий застосунок "Shade Tweak" із лаунчера → введи колір у форматі
`AARRGGBB` → "Зберегти й застосувати". Якщо ефект не з'явився одразу:
```
su -c "killall com.android.systemui"
```

## Якщо не спрацювало

Відкрий LSPosed Manager → Logs, знайди рядки з тегом `ShadeTweak`:
- `updateWindow заховано успішно` / `access$updateResources заховано
  успішно` — хук встановився, але клас, можливо, не єдине джерело кольору.
- `hook FAILED` — назва методу/класу в цій точній збірці HyperOS
  відрізняється від знайденої (буває при регіональних білдах або після
  оновлення HyperOS). Скинь мені точний текст помилки — скоригую.

## Автоматичний перезапуск SystemUI

Застосунок сам виконує `su -c "killall com.android.systemui"` після кожного
збереження кольору чи перемикача - Termux більше не обов'язковий для цього.
При першому натисканні KernelSU покаже запит на дозвіл root для
com.shadetweak.hyperos - підтверди його (окремо від дозволу, який вже
виданий LSPosed/ZygiskNext).

## Оновлення: другий шар (ScrimController) — експериментально

Якщо після основного фіксу лишається залишковий сірий відтінок — це окремий
AOSP-механізм `ScrimController`, який також відповідає за затемнення екрана
блокування/AOD/PIN. У застосунку "Shade Tweak" з'явився другий, окремий
перемикач для цього (розділ "Експериментально", вимкнено за замовчуванням).
Хук звужено тільки на стан `UNLOCKED` (шторка над розблокованим домашнім
екраном) - блокування/AOD/PIN не зачіпає. Вимкни цей перемикач одразу, якщо
помітиш будь-які дивні ефекти поза шторкою.

## Оновлення HyperOS

Після великого оновлення системи внутрішні назви класів можуть змінитись —
модуль доведеться повторно проаналізувати на новій версії `MiuiSystemUI.apk`.
